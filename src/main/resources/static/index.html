Comportement

Mode d'exécution

Le mode ne peut que restreindre l'autonomie déclarée d'une capacité, jamais l'élargir.

Autonomie par capacité

Toute capacité non réglée est interdite : le droit d'agir ne s'hérite pas. Le champ de droite est le plancher de confiance propre à la capacité — il ne peut que relever le plancher global, jamais l'abaisser.

Seuil de confiance

Plancher global : en deçà, une action autonome repasse par une validation humaine au lieu de s'exécuter. Chaque capacité peut exiger davantage, jamais moins.

Notifications

Vérifie kex.agent.supervision.notify.webhook-url sans attendre qu'une anomalie réelle le découvre en échec — la seule capacité dont le système cible est une personne.

Charte

Ce que l'exploitant veut que l'agent rappelle à chaque échange, en plus du prompt système. Donnée de référence : elle restreint ce que l'agent propose, elle n'élargit jamais une autonomie, une permission ou une approbation. Un seul auteur possible, ADMIN — jamais approuvée par revue, ce serait se faire approuver par soi-même.

File de revue

Compétences en attente, tous propriétaires confondus, la plus ancienne d'abord. Approuver ou rejeter reste un geste transverse — voir l'API — précisément parce qu'une compétence tirée d'un refus appartient à l'opérateur qui a refusé, jamais à l'administrateur qui tranche.

Bibliothèque de compétences

Ce que la bibliothèque approuvée pèse réellement dans le prompt : ce qui agit, ce qui dort au-delà du plafond d'injection, ce qui n'a pas été revu depuis longtemps, ce qui double un autre titre. Un rapport, jamais une action — le curateur signale, un humain nommé retire.

État inconnu

Couverture partielle

Le cycle n’a pas lu toutes les sources prévues ; une absence d’anomalie ne peut donc pas être affirmée.

Confiance

Indique la solidité du diagnostic à partir des observations disponibles, pas une garantie de réussite.

Autonomie

Détermine si une capacité est automatique, soumise à validation humaine ou interdite.

Modèle de langage

Lue dans la configuration résolue de l'instance — variables d'environnement comprises — et non dans un fichier : ce qui est affiché est ce qui tourne. En lecture seule, le client du modèle étant câblé au démarrage ; un champ modifiable ici accepterait une valeur que l'échange suivant ignorerait. Ces réglages se posent en variables d'environnement, et prennent effet au redémarrage de l'agent.

Détection

Ces seuils sont transmis au modèle comme critères explicites : une anomalie doit se justifier par une mesure, pas par une impression.

Serveurs MCP

La vue technique : ce que l'agent peut réellement observer et actionner. Le tableau de bord métier n'en est pas saturé.

Catalogue recommandé

Deux points d'accès distants sélectionnés par l'équipe, sans commande locale ni destination modifiable. Statique côté serveur : chargé avec le reste de la vue, sans appel à un service tiers.

Découverte de serveurs MCP

Docker MCP Catalog et le registre officiel MCP, chacun éteint par défaut côté serveur. Chaque candidat porte une note de confiance sur 100 et, le cas échéant, un motif de disqualification — calculés côté serveur, jamais recalculés ici. Une source interrogée à la demande, pas au sondage de fond : elle appelle un service tiers.

Cluster Kafka

Relevé par les outils du serveur MCP, jamais recalculé ici : les verdicts de retard sont ceux que l'outil rend, et une mesure absente s'affiche « non mesurée », pas zéro.

Mémoire long-terme

Ce que le modèle retient au-delà d'une conversation, via l'outil remember_fact. Lecture et suppression seulement : écrire n'est jamais un geste d'opérateur.

Base de connaissance

Aucune liste exhaustive n'existe côté serveur : le magasin vectoriel n'expose qu'ajouter, retirer et chercher par similarité — jamais énumérer. Rechercher ici applique les mêmes seuils qu'avant un échange réel, pour voir ce que le modèle verrait.
